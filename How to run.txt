========================================================
  HOW TO RUN - CRIMENO ML PIPELINE
========================================================

CHOOSE YOUR ANOMALY WORKER: Qwen (local GPU) or Groq (API, recommended)
Then follow the matching set of commands below.


========================================================
  OPTION A: GROQ (recommended - zero VRAM, fast, smart)
========================================================
Prerequisites (one time):
  pip install groq python-dotenv
  Put your API key in .env: GROQ_API_KEY=gsk_YOUR_KEY
  For the VLM layer (Qwen2.5-VL, runs LOCALLY - free, no API key):
    pip install "transformers>=4.49" accelerate
    (torch and pillow are already installed from the tracker setup)

Step 1 - Broadcaster:
  python video_broadcaster.py videos/shop.mp4

Step 2 - Groq anomaly worker:
  python groq_anomaly_worker.py --ws_url ws://127.0.0.1:3000/ws/groq --decision-frames 60 --tracker-every 5

  --decision-frames: minimum video frames between two Groq API calls (= cost knob, default 60).
                     Groq fires AT MOST once per this many frames regardless of how fast VLM runs.
  --tracker-every:   tracker's --send_every_n_frames value (default 5). Used to bound how far a
                     tracker record can be from a VLM anchor when attaching enrichment context.
  Cost is fully decoupled from VLM speed: running VLM faster gives fresher context but never
  increases API spend. Only lower --decision-frames to increase decision frequency.

Step 3 - YOLO Tracker:
  python tracker_worker.py --device cuda --ws_url ws://127.0.0.1:3000/ws/tracker --send_overlay 0 --send_every_n_frames 5 --anomaly-endpoint tcp://127.0.0.1:5581

Step 4 - VLM layer (Qwen2.5-VL-3B-Instruct, full-frame scene analysis — PRIMARY decision driver / anchor):
  python vlm_worker.py --device cuda --every 60 --ws-url none --anomaly-endpoint tcp://127.0.0.1:5581

  VLM is the decision ANCHOR: each VLM frame triggers a potential Groq decision (subject to the
  --decision-frames throttle above). The nearest tracker frame is attached automatically as
  enrichment context.
  One single structured call per frame returns rich JSON: scene description, people actions,
  appearance, weapon description, + binary cues (gun, knife, reaching counter, hands up,
  face concealed, aggression).
  Model options:
    --vlm_model Qwen/Qwen2.5-VL-3B-Instruct   (default, ~8 GB VRAM)
    --vlm_model Qwen/Qwen2.5-VL-7B-Instruct   (higher quality, ~16 GB VRAM)
  WS: use --ws-url none unless the NestJS backend actually exposes a /ws/vlm route (it does NOT by
  default — a missing route causes "did not receive a valid HTTP response" and the worker hangs
  retrying). The VLM reaches Groq via the anomaly-endpoint (5581) regardless of WS.

NOTE: Florence is no longer required. florence_worker.py still exists but is not launched.


========================================================
  OPTION B: QWEN (local, requires ~6GB VRAM)
========================================================

Step 1 - Broadcaster:
  python video_broadcaster.py videos/shop.mp4

Step 2 - Qwen anomaly worker:
  python qwen_anomaly_worker.py --device cuda --ws_url ws://127.0.0.1:3000/ws/qwen

Step 3 - Florence:
  python florence_worker.py --device cuda --every 30 --ws_url ws://127.0.0.1:3000/ws/florence

Step 4 - YOLO Tracker:
  python tracker_worker.py --device cpu --ws_url ws://127.0.0.1:3000/ws/tracker --send_overlay 0 --send_every_n_frames 10


========================================================
  EXTRAS
========================================================

Florence background options (--bg flag):
  --bg black   remove background (black)
  --bg blur    blur background
  --bg focus   crop + focus on motion area

Florence with preview window:
  python florence_worker.py --device cuda --every 30 --bg blur --test show_image

Tracker with preview window (no backend needed):
  python tracker_worker.py --device cpu --send_overlay 0 --send_every_n_frames 2 --test show_image
